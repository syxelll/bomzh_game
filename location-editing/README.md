# Редактирование улицы в Blender

**Актуальная секция по референсу:** [courtyard-reference.blend](https://raw.githubusercontent.com/syxelll/bomzh_game/main/location-editing/courtyard-reference.blend). Это самостоятельный процедурный вариант с упакованными текстурами; исходный файл пользователя не изменён. Подробности ниже.

[Скачать street-template.blend](https://github.com/syxelll/bomzh_game/raw/refs/heads/main/location-editing/street-template.blend)

Файл создан в Blender 5.2.3 из реальных мешей исходной процедурной улицы (`src/world.js`). Это редактируемая копия окружения, а не автоматическая связь Blender с игрой. Дорога, дома, окна, фонари, лавочки, урны и бутылки сохранены отдельными объектами. Текстуры кирпича, асфальта с трещинами, бетона, ржавчины и надписей перенесены из текущей игры вместе с UV и упакованы внутрь `.blend`: отдельные файлы изображений скачивать не нужно. Персонажей, анимаций и игровой логики в файле нет.

## Что редактировать

- `EDIT_26m_MAIN`: основная секция, X от 0 до 26 метров. Здесь меняй дома, дорогу, реквизит и материалы.
- `REFERENCE_NEIGHBOR_-1`, `REFERENCE_NEIGHBOR_1`: соседние секции для проверки стыков. Выделение заблокировано; коллекции можно скрыть в Outliner.
- `GUIDES_DO_NOT_EXPORT`: границы секции, зона движения, начало следующей секции и габарит персонажа высотой 1,85 м. Это только ориентиры.
- `PREVIEW_CAMERA_AND_LIGHTS`: пример камеры игры и свет. Камера в самой игре движется и меняет приближение, поэтому проверять надо и широкий кадр, и крупный, и вертикальный экран.

1 единица = 1 метр. В Blender: X — вдоль улицы, Z — вверх, Y — глубина. Перевод в игру: game X = Blender X, game Y = Blender Z, game Z = -Blender Y. Земля около Z=0; игровая полоса по Blender Y от -2.1 до 2.0. Передний край дороги расположен в отрицательной стороне Y, дома — в положительной. Объекты стоят в игровых мировых координатах, их Origins перенесены в центр каждой детали для удобного перемещения. Основная секция содержит 426 мешей; детали сгруппированы в Buildings_and_details, Road_and_sidewalks, Street_props и Pickup_references.

## Рекомендуемый порядок

1. Сохрани копию как `street_01.blend`. Оставь масштаб и положение секции X=0..26.
2. Сначала расставь крупные формы: дома, дорогу, тротуар. Проверь кадр через Numpad 0 и силуэт героя по габаритному ориентиру.
3. Оставь полосу движения свободной. Сейчас столкновения с декорациями не вычисляются: поставленная поперёк дороги урна или стена сама по себе не станет препятствием. Для препятствий потребуется отдельно добавить коллизии в игру.
4. По краям X=0 и X=26 сохрани одинаковые высоту, ширину и материал дороги/тротуара. Не ставь на стыках поперечные стены: уровни бесконечные, секции должны соединяться.
5. Добавь детали и материалы. Для первого варианта достаточно простых Principled BSDF материалов с Base Color/Roughness. Процедурные шейдеры Blender нужно будет запечь перед GLB; внешние текстуры упакуй через File → External Data → Pack Resources.
6. Бутылки — ориентиры текущего размещения; подбор предметов генерируется кодом. Новые позиции бутылок, появления врагов и интерактивных объектов согласуем отдельно, не встраивай их как обычные декоративные меши для финального экспорта.
7. Пришли `.blend` через Drive. Достаточно исходного файла: я подготовлю экспорт и подключение. Для самостоятельного экспорта выдели только окружение основной секции, File → Export → glTF 2.0 → GLB → Selected Objects. Не включай соседние секции, ориентиры, свет и камеру. Надписи сейчас являются текстурой на плоскости.

Лучше сначала сделать одну готовую секцию и проверить её в игре, затем 3–5 вариантов с теми же стыками. Они смогут чередоваться при бесконечном прохождении. Пока файл не подключён вместо процедурной улицы — внешний вид игры этим коммитом не меняется.

## Повторное создание шаблона

После `npm install`:

```sh
node scripts/export-street.mjs
blender -b --factory-startup --python scripts/blender/export_street_template.py
```

Node-экспортёр сам запускает временный Vite-сервер и Chromium (по умолчанию `/usr/bin/chromium`, переопределяется `CHROMIUM_PATH`), чтобы получить настоящие canvas-текстуры. Вершины с учётом всех InstancedMesh, UV, материалы и PNG передаются через `/tmp/street-meshes.json`. Пути можно переопределить: аргументом Node-скрипта и параметрами Blender-скрипта `-- --input PATH --output PATH`.

Освещение Blender является ориентиром: Three.js и Blender рендерят свет по-разному. Окончательный свет настраивай в [редакторе игры](https://syxelll.github.io/bomzh_game/?editor=lighting). Предпросмотр в Blender рассчитан на Cycles. Коллекции ориентиров скрыты от рендера, соседние секции заблокированы только от выделения — в рендере они видны.

## Модульный процедурный шаблон — удобнее для замены объектов

[Скачать street-modular.blend](https://raw.githubusercontent.com/syxelll/bomzh_game/main/location-editing/street-modular.blend)

Вместо сотен независимых деталей здесь 48 общих объектов-образцов и 12 процедурных фасадов на трёх секциях. Всё работает на стандартных Geometry Nodes и простых драйверах Blender 5.2.3: дополнения и запуск Python для редактирования не нужны. Текстуры упакованы. В файле есть русская инструкция `КАК_РЕДАКТИРОВАТЬ` в Text Editor.

### Изменить все окна, двери или фонари

1. В Outliner открой `MODULE_LIBRARY_EDIT_HERE`. Библиотека расположена за улицей, по Y от 15 м.
2. Выбери `ASSET_WINDOW_01`, нажми **Numpad .**, чтобы приблизить его. В **Edit Mode** меняй форму окна — все фасады обновятся. У других деталей тот же принцип: `ASSET_DOOR_*`, `ASSET_STREETLIGHT_*`, `ASSET_BENCH_*`, `ASSET_BUILDING_SHELL_*` и т. д. Разные варианты материала/формы имеют собственные образцы.
3. Для замены своим готовым мешем сначала примени к нему **Rotation & Scale** и поставь Origin снизу по центру. Выдели старый `ASSET_*` первым, новый объект последним, чтобы новый был **активным**. **Ctrl+L → Link Object Data** перенесёт новый меш в объект-образец, сохраняя его имя и трансформации. Все ссылки обновятся. После замены лишний объект-донор можно удалить.
4. Для замены только одного установленного модуля выбери его и в модификаторе укажи другой **Source module**. У фасада `WINDOW_GRID_*` это поле **Window module**. Новый объект должен иметь сопоставимые размеры и Origin снизу по центру.

### Настроить или переместить дом

Выбери `HOUSE_0_0_CONTROLS` (или другой `HOUSE_*_CONTROLS`). Перемещение, вращение и масштабирование контроллера воздействуют на весь дом вместе с окнами, дверью, лестницей и трубой.

В **Object Properties → Custom Properties**:

| Параметр | Что меняется |
|---|---|
| `floors` | Число рядов окон и высота корпуса дома |
| `columns` | Число окон в ряду |
| `window_spacing` | Шаг окон по горизонтали, в метрах |
| `floor_spacing` | Шаг этажей, в метрах |

На первом этаже оставлен центральный проём для двери. Во время правок следи, чтобы окна помещались по ширине фасада. Лестницы и трубы — отдельные заменяемые модули: при изменении числа этажей они не достраиваются автоматически, их нужно подогнать. Высота корпуса меняется масштабированием по вертикали; для новой архитектуры можно заменить сам корпус.

Рабочая секция по-прежнему `EDIT_26m_MAIN`, X=0..26 м. Не включай в игровой экспорт библиотеку образцов, соседей и ориентиры. Проще прислать исходный `.blend`: я подготовлю GLB с вычисленными модификаторами. Генераторы Geometry Nodes выполняются в Blender, в браузер переносится их результат. Сам файл автоматически с игрой не синхронизируется.

### Пересоздать и проверить

```sh
node scripts/export-street.mjs
blender -b --disable-autoexec --python scripts/blender/modular_street_template.py
blender -b --disable-autoexec --python scripts/blender/verify_modular_street.py
```

Проверка сравнивает положение всех вершин трёх секций с исходной улицей с допуском 0,1 мм, меняет число этажей, проверяет замену меша-образца и наличие упакованных текстур. Базовый `street-template.blend` нужен генератору для материалов, ориентиров, камеры и света.

## Подключённая авторская локация

В игре используется `public/models/street.glb`, экспортированный из обновлённого пользователем файла Drive `1FpkXyXUOW-DkHozOACyzlzPDYigzBwjY`. Рабочая секция `EDIT_26m_MAIN` экспортируется с вычисленными Geometry Nodes и модификаторами. Образцы, соседние секции, ориентиры и статические копии подбираемых бутылок исключаются. Игровые бутылки по-прежнему создаёт `Street`, пять секций переиспользуют одну геометрию и текстуры.

Экспорт содержит 27 116 треугольников. После объединения совместимых мешей и сжатия WebP файл занимает около 10,8 МБ. Цветные карты сохраняются до 2048 px, нормали и служебные карты — до 1024 px. Преобразования Gamma/Invert для шероховатости вычисляются в текстуры; кирпичная карта высот преобразуется в карту нормалей. Исходный `.blend` не изменяется и не добавляется в репозиторий.

```sh
blender -b --disable-autoexec --python scripts/blender/export_authored_street.py -- --source /path/to/street.blend --output /tmp/street-raw.glb
node scripts/optimize-street.mjs /tmp/street-raw.glb
npm run build
node scripts/standalone.mjs
```

При следующем обновлении меняй версию URL `street.glb` в `src/main.js`, чтобы сбросить кеш. Материалы локации получают отражение пасмурного неба, связанное с настройками света. Переднее мощение продолжается за камерой с исходным UV-масштабом, чтобы край сцены не появлялся на вертикальном экране. GLB сохраняет исходную секцию без этого игрового продолжения.

`street-template.blend` и `street-modular.blend` остаются исходными шаблонами. Актуальный авторский исходник — файл пользователя по указанному Drive ID; он не перезаписывается генераторами шаблонов.

## Двор по референсу: стилизация и редактирование

`courtyard-reference.blend` использует приглушённые кирпич, известняк, тёмный металл, янтарные бутылки и направленный тёплый свет. Рабочая секция — 26 м; 29 468 треугольников, около 3,7 МБ в игровом GLB. Это первая интерпретация референса, а не фотограмметрическая копия изображения.

- `MODULE_LIBRARY_EDIT_HERE`: общие образцы. Основное окно — `ASSET_WINDOW_01`, дополнительные — `ASSET_COURT_WINDOW_2/3`. Geometry Nodes распределяет три варианта штор/жалюзи по фасадам.
- `HOUSE_0_*_CONTROLS`: этажи, колонки, шаг окон и этажей в Custom Properties. Для перемещения дома выбирай контроллер целиком. Карнизы и реквизит остаются отдельными дочерними модулями.
- `FENCE_ROW_Left` и `FENCE_ROW_BehindDumpster`: поля Panels и Fence module в модификаторе; стандартная ширина панели 2,4 м. Сетка — RGBA-текстура с отсечением альфа-канала, без тысяч проволочных полигонов.
- `COURT_*`: заменяемые фонари, урны, шины, мешки, открытый контейнер, бумага, граффити и полосы грязи у основания стен. Меняй исходный ASSET-меш или Source module, сохраняя origin и масштаб.
- Соседи — живые инстансы рабочей коллекции со смещением ±26 м. Правки основной секции сразу видны на стыках.

Материалы созданы программно и упакованы в PBR-карты. В Blender их можно заменить или рисовать по ним; для изменения генерации используй `scripts/blender/build_reference_courtyard.py`. Внутри `.blend` есть русская инструкция `СТИЛЬ_И_МОДУЛИ`. Дополнения и разрешение на запуск Python при открытии не нужны. `PICKUP_REFERENCE_*` — ориентиры, реальные бутылки создаёт игра. Не экспортируй библиотеку, соседей, ориентиры и камеру.

```sh
blender -b --disable-autoexec --python scripts/blender/build_reference_courtyard.py -- --source /path/to/user-street.blend --output /tmp/courtyard-reference.blend
blender -b --disable-autoexec --python scripts/blender/verify_reference_courtyard.py -- --blend /tmp/courtyard-reference.blend
blender -b --disable-autoexec --python scripts/blender/export_authored_street.py -- --source /tmp/courtyard-reference.blend --output /tmp/courtyard-raw.glb
node scripts/optimize-street.mjs /tmp/courtyard-raw.glb
```

Проверка нового света без перезаписи личных сохранённых настроек: `?quality=high&lighting=reference`. В обычной ссылке сохранённые пользователем настройки освещения продолжают действовать.
