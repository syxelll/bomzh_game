# Дворовые истории

Первый браузерный 3D-прототип игры для Telegram Mini Apps: улица, модели пользователя, сбор бутылок, обмен на монеты, разные типы противников и подкрепление.

## Запуск

Нужен Node.js 22.12+ (проверено на 24.19).

```sh
npm ci --cache /workspace/.npm-cache
npm run dev -- --port 5173
```

`npm run build` собирает готовый статический сайт в `dist/`. Для Telegram разместите содержимое этой папки на HTTPS-хостинге и укажите адрес как Mini App / кнопку меню бота через BotFather. Telegram SDK подключён: приложение сообщает о готовности и разворачивает окно. В обычном браузере игра работает без Telegram. Бот и публичный хостинг ещё не созданы.

## Как играть

- WASD или стрелки / экранные кнопки — движение по улице.
- J — быстрый удар. Третий последовательный удар получает бонус урона.
- K — более дальний пинок.
- L — круговой удар с перезарядкой.
- Пробел или кнопка «Рывок» — быстрое уклонение по направлению движения (без движения — вперёд). Рывок можно использовать для отмены своего удара.
- Бутылки подбираются автоматически при приближении.
- У пункта приёма в правом конце улицы нажмите E или кнопку обмена. Курс: 3 монеты за бутылку.
- Жёлтая полоса над противником предупреждает о готовящемся ударе. Можно отойти.
- E или экранная кнопка рядом с жителем — начать разговор. Во время диалога бой и движение приостановлены; Esc закрывает разговор.
- Q или кнопка «Задания» — журнал с целями и прогрессом.
- Для завершения двора выполни и сдай все три поручения жителей. Остальные бутылки и противники необязательны.

На узких экранах автоматически отключаются тени и снижается разрешение. Параметр `?quality=low` включает этот режим вручную.

## Проверки

```sh
npm test
npm run build
# В другом терминале должен работать dev-сервер на порту 5173.
npm run test:browser
node tests/combat-smoke.mjs
```

Браузерные проверки используют системный `/usr/bin/chromium` и программный WebGL. Проверяют загрузку моделей, движение, подбор бутылки, экранные кнопки, бой и обмен. Это не измерение производительности реального телефона.

## Модели

В `public/models/` — облегчённые GLB с текстурами и скелетами. Перед экспортом запечены цвет без освещения, шероховатость и нормали. В игровой версии текстуры уменьшены до 512 px и записаны в lossless WebP внутри GLB; тяжёлая геометрия без shape keys упрощена. Более подробные исходные экспорты сохранены отдельно в `/workspace/model-exports/`, оригинальные Blender-файлы — в `/workspace/model-sources/` текущей облачной среды.

Повторная подготовка моделей в этой среде: Blender 5.2.3, скрипты `/workspace/model-sources/bake_export.py` и `mobile_models.py`, затем `node scripts/optimize-models.mjs`. При запуске Blender используйте `--disable-autoexec --python-exit-code 1`. Скрипты требуют исходных файлов за пределами репозитория. Для обычного запуска игры Blender не нужен.

## Границы прототипа

Анимация процедурная и требует художественной доработки. Прогресс хранится только до перезагрузки страницы; серверной экономики, авторизации Telegram и платежей нет. Клиентские монеты подходят для прототипа, но не для защищённой игровой экономики. Для запуска в Telegram остаются HTTPS-размещение и настройка бота.

## Один HTML-файл для проверки

```sh
npm run build
node scripts/standalone.mjs
```

Получится `dist/game-standalone.html`: код и модели встроены в файл, Telegram SDK исключён. Файл можно открыть в настольном браузере без отдельного сервера.

Скрипты подготовки Blender также включены в `scripts/blender/`. Их рабочие пути настроены на текущую облачную среду; оригинальные `.blend` не включены в Git, игровые GLB включены.

## Анимация боя

Кулак, пинок и вертушка имеют отдельные фазы замаха, контакта и возврата. Кулак чередует руки, у пинка сначала поднимается колено. Урон синхронизирован с контактной позой; попадание даёт короткую остановку движения, вспышку и реакцию корпуса. Враги сначала показывают замах, затем выполняют удар. Камера приближена для читаемости на телефоне.

`src/animation.js` использует исходные имена костей из `userData.name` (Three.js удаляет точки из `bone.name`) и рассчитывает матрицы деформации без разложения масштабированных управляющих костей. Для визуальной проверки поз при работающем dev-сервере: `node tests/animation-review.mjs` и `node tests/animation-review.mjs enemy`.

## Жители и поручения

- **Семён**, у начала улицы: найти 3 бутылки и вернуться. Награда — 12 монет; бутылки остаются у игрока.
- **Гриша**, у середины улицы: победить 3 противников, включая громилу, и вернуться. Награда — 25 монет и восстановление 20 здоровья (до максимума 100).
- **Варя**, у пункта приёма: сдать 5 бутылок. За каждую платит 3 монеты, а за поручение отдельно выдаёт 20 монет. В её диалоге есть кнопка сдачи бутылок.

У жителей над головой есть имена и маркеры. Рядом появляется кнопка разговора. Прогресс учитывает действия с начала текущего прохождения, в том числе до принятия задания; за наградой нужно обратиться к жителю. Повторная выдача награды заблокирована. Журнал и поручения пока не сохраняются после перезагрузки. NPC используют временные геометрические модели, боевые модели пользователя сохранены.

`npm test` проверяет состояния поручений, награды и ограничения. `node tests/quests-smoke.mjs` при работающем dev-сервере проверяет принятие задания, паузу разговора, сбор бутылок, возвращение к NPC, получение награды и запись в журнале.

## Динамика боя и камера

Выносливость ограничивает непрерывные атаки: кулак — 10, пинок — 24, вертушка — 38, рывок — 22 из 100. Восстановление начинается через 0,8 секунды после действия; во время разговора ресурс не восстанавливается. Рывок даёт короткую неуязвимость и требует перезарядки.

У противников три типа: быстрый задира сближается и делает выпад; боец держит давление; громила медленно готовит сильный круговой удар. Кулак не прерывает замах громилы — используй пинок, вертушку или отход. Зона на земле предупреждает об атаке. Направление обычного удара фиксируется в момент замаха, поэтому его можно обойти. Противники заходят с разных сторон. После первой победы и продвижения во вторую половину улицы появляется предупреждение о подкреплении, затем ещё двое врагов.

Камера плавно сопровождает героя, смещает взгляд по ходу движения, учитывает ближайших противников и расширяет кадр в бою. В диалоге она переводит внимание на пару собеседников. Попадания дают небольшой затухающий толчок; при системной настройке уменьшения движения толчки выключены. На телефоне дистанция адаптируется к узкому кадру.

`node tests/dynamics-smoke.mjs` проверяет рывок, восстановление выносливости, наличие разных типов врагов и отображение на настольном и мобильном экране. Правила попадания, расходы ресурсов и кадрирование отдельно проверяются через `npm test`. Производительность на настоящем телефоне всё ещё требует проверки.
