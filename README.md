# Дворовые истории — бесконечная улица

3D beat ’em up для браузера и Telegram Mini Apps. Иди вправо, побеждай группы противников и проходи как можно больше участков. Финального уровня нет; побочные задания, NPC и обмен бутылок сейчас убраны из режима.

## Запуск

Нужен Node.js 22.12+ (проверено на 24.19).

```sh
npm ci
npm run dev
```

Открой адрес после `Local:` в терминале. Команды выполняются в папке с `package.json`; окно сервера оставь открытым.

```sh
npm run build
node scripts/standalone.mjs
```

`dist/` — готовый статический сайт для HTTPS-хостинга. `dist/game-standalone.html` содержит код, модели и Actions в одном файле для открытия в настольном браузере без отдельного сервера. Telegram SDK исключён из одиночного файла. В обычной сборке подключены Telegram ready/expand; публичный хостинг и бот ещё не настроены.

## Управление

- WASD / стрелки или экранные кнопки — движение.
- J — кулак без расхода выносливости. Во второй половине удара можно заранее нажать следующий; третий удар серии усиленный и сбивает с ног.
- K — пинок (14 выносливости).
- L — струя по нескольким целям (32 выносливости).
- Пробел / «Рывок» — уклонение с короткой неуязвимостью (16 выносливости). Направление берётся из кнопок движения; без них — вперёд. Можно отменить свой удар.
- Esc / Ⅱ — пауза.

Выносливость восстанавливается после короткой паузы в использовании сильных приёмов. При получении урона герой кратко теряет инициативу; рывок позволяет уйти. Лежащие враги временно не атакуют и не получают повторных ударов, затем встают. Громила выдерживает кулаки без прерывания замаха.

## Бесконечное прохождение

Участки генерируются последовательно без последнего уровня. Растут характеристики врагов, размер группы и число волн. Одновременно приходит максимум четыре противника, позднее — до трёх волн за участок. Здоровье, скорость и урон имеют предел роста; дальше меняется последовательность стычек.

Перед боем камера плавно приближается. Видимых линий или ворот на земле нет. Враги создаются целиком за пределами текущего кадра и прибегают с его краёв; точка входа рассчитывается с учётом размеров экрана и текущего положения камеры. Пока группа не побеждена, герой остаётся в боевом кадре. После победы появляется «Дальше» и открывается следующий участок.

За победу над участком: 100 × номер участка очков, 8 здоровья и восстановление выносливости. Бутылки автоматически подбираются за 10 очков; каждая пятая восстанавливает 5 здоровья. Рекорд сравнивается сначала по пройденным участкам, затем по очкам и сохраняется в localStorage этого браузера. Общей сетевой таблицы лидеров пока нет. После поражения можно начать новый забег.

Окружение подгружается кусками: в памяти остаются пять соседних фрагментов улицы. Старое окружение и тела побеждённых противников удаляются; история участков не накапливается.

## Анимации из Blender

К герою подключены обновлённые `idle`, `walk` и три Action `_combo`; подробности актуальной цепочки ниже. Матрицы с ограничениями Blender сохранены в `public/models/hobo-actions.json`. Видимая модель и запечённые текстуры сохранены в `hobo.glb`.

Удары используют авторские Action, струя, добивание и реакции пока процедурные. Перемещение корневой кости по земле убрано из idle/walk, чтобы анимация не смещала модель отдельно от игровой позиции. Исходный `.blend` не изменён.

В текущей облачной среде оригиналы находятся в `/workspace/model-sources/`, исходные экспорты — в `/workspace/model-exports/`. Скрипты подготовки в `scripts/blender/` требуют Blender 5.2.3 и этих файлов. `export_user_actions.py` извлекает Actions без выполнения встроенных скриптов; пути настроены на облачную среду. Для запуска игры Blender не нужен. Обновление: `blender -b --factory-startup --disable-autoexec --python scripts/blender/bake_updated_hobo.py`, затем `mobile_models.py -- hobo-updated`, `node scripts/optimize-models.mjs hobo-updated`, `export_user_actions.py -- --source /workspace/model-sources/hobo-updated.blend --baseline /workspace/model-exports/hobo-updated/hobo-updated_baked.blend`. Исходный файл не перезаписывается.

## Проверки

```sh
npm test
npm run build
# Dev-сервер должен работать на порту 5173:
npm run test:browser
node tests/dynamics-smoke.mjs
npm run test:endless
node tests/animation-review.mjs
```

Браузерные проверки используют `/usr/bin/chromium` и программный WebGL; могут выполняться несколько минут. Проверяются управление, ресурс рывка, входы вне кадра, несколько участков подряд, ограниченный размер мира, авторские Actions и сохранение рекорда после перезагрузки. Модульные проверки генерируют 1500 участков и проверяют паузу, рекорды, разные размеры кадра и данные анимаций. Это не измерение производительности настоящего телефона.

Модели облегчены, текстуры запечены и встроены в GLB как lossless WebP. Инструменты повторной оптимизации находятся в `scripts/optimize-models.mjs` и зависят от сохранённых промежуточных файлов вне репозитория. Инструкции установки облачной среды используют `npm ci --cache /workspace/.npm-cache` из-за ограничений домашнего каталога.

### Обновление боя и камеры

Персонажи плавно поворачиваются по направлению движения; прямые удары проверяют это же направление. Исправлены оси плеча/локтя процедурных анимаций и интерполяция вращений авторских Actions. Камера приближена. Подписи над врагами убраны, полоски здоровья сохранены.

Попадания дают 12% суперсилы, обычная победа ещё 18%. На 100% нажми **F** или кнопку **Добивание** рядом с противником (до 2.8 м). Герой выполняет одиночный апперкот: отдельная камера на пару, замедление при попадании, отлёт и мгновенная победа независимо от здоровья врага. Остальной бой и появление волн приостановлены; Esc приостанавливает и саму сцену. При отсутствии доступной цели заряд сохраняется. Анимация добивания пока процедурная; её можно заменить отдельным Blender Action.

Невидимая граница на старте не пускает левее начальной позиции. После зачистки участка она сдвигается к месту победы, сохраняя возможность отступать в текущем бою.

Проверка добивания реальным управлением: `node tests/encounters-smoke.mjs --super` (для вертикального экрана добавить `--mobile`).

Клавиша **L / Струя** заменяет прежнюю вертушку: персонаж остаётся одетым, принимает отдельную позу и направляет жёлтую струю вперёд. Дальность 3.2 м, урон 34 один раз по каждому врагу за применение, стоимость 32 выносливости. Враги сзади и сбоку не задеваются. Попадания во время активной струи прерывают атаку противника и ненадолго оглушают его.

### Монеты, магазин и бонусы

Монеты зачисляются сразу и остаются между забегами: бутылка — 3, обычный противник — 3, громила — 8, пройденный участок — 15. Кошелёк, купленные образы и выбранный образ сохраняются в localStorage этого браузера. Переноса между устройствами пока нет. При недоступном хранилище магазин показывает, что сохранение действует только до закрытия страницы.

Магазин открывается кнопкой с монетами или с экрана поражения и ставит бой на паузу. «Тёмные очки» стоят 60, «Король двора» (золотые очки и красный шарф) — 180. Купленный образ надевается сразу; оригинальный образ доступен бесплатно. Косметика не меняет силу, здоровье, скорость и награды.

После поражения можно один раз за забег получить второй шанс: 60 здоровья, полную выносливость и 3 секунды неуязвимости. Волна и противники сохраняются. Либо можно удвоить все заработанные в забеге монеты — это завершает забег и закрывает возможность воскреснуть. Повторное нажатие и запоздавший callback другого забега не выдают награду второй раз. Перезапуск сбрасывает право на бонусы, сохраняя кошелёк и покупки.

Сейчас используется **бесплатный тестовый провайдер** `src/rewards.js`: рекламы и реальных денежных покупок нет; интерфейс прямо сообщает, что бонусы бесплатные. Для rewarded ads нужно заменить провайдер на выбранный SDK: `request({placement,runId})` возвращает `{completed:true}` только после подтверждённого полного просмотра. Отмена, ошибка и таймаут не дают бонус; блокировка кнопок снимается. Проверки: `npm test`, `node tests/economy-smoke.mjs`.

Для настоящих покупок через Stars нужен backend: проверка Telegram initData и платежей, серверный баланс и инвентарь, идемпотентная выдача по идентификатору платежа. Локальный кошелёк рассчитан на прототип и игровые монеты; он не защищает платные товары от изменения через инструменты браузера. Фиктивных кнопок оплаты Stars в игре нет.

### Переходы поз и привязка аксессуаров

Переходы используют цепочки суставов деформирующего рига, а не независимое смешивание мировых матриц. Координаты родителей нормализуются без потери исходных масштабов управляющих костей. Увеличение кисти из `jab_01` компенсируется целиком вместе с пальцами; для процедурных движений используется авторская форма кистей из idle. Возврат после контакта — отдельный плавный переход. Шапка и детали лица обновляются после сглаживания по окончательной позе кости, как и магазинная косметика. Проверка `npm run test:animation` прогоняет 559 кадров ходьбы, ударов, стойки, добивания и получения урона, измеряя вершины кистей и точность привязки шапки.

### Визуальный ориентир двора

Окружение приближено к кирпичному двору из референса: фасады с кладкой, пожарные лестницы, кондиционеры, трубы, бельё, мусор и растрескавшийся асфальт; освещение стало нейтральнее, добавлены мягкие контактные тени под персонажами. Это процедурная интерпретация настроения референса, без набора фотореалистичных сканов. Статические детали объединяются в InstancedMesh, мир сохраняет только пять секций; материалы и геометрия переиспользуются. Экспортёр улицы учитывает все экземпляры объектов при подготовке Blender-шаблона.

### Джинсовая ткань и шаги

Карта штанов перезапечена с явной привязкой Texture Coordinate → UV к исходной развёртке. Атлас GameUV, геометрия и риг сохранены; цвет, нормали и шероховатость джинсов имеют разрешение 1024. Общий экспорт также фиксирует исходные UV до создания bake-развёртки и сохраняет для джинсов 1024 при оптимизации. Точечное повторное запекание: `scripts/blender/rebake_denim.py`, затем `node scripts/patch-denim.mjs`.

Обычная скорость героя — 1.8 м/с. Фаза шага рассчитывается по фактически пройденному расстоянию и длине цикла, измеренной по авторской траектории стоп. На границе, при паузе и без перемещения шаг не продолжает проигрываться. Процедурная походка противников также зависит от расстояния. После позирования опорная подошва доводится до плоскости дороги по нескольким реальным вершинам ботинок; поднятая нога при пинке остаётся в воздухе. Падения и постановочный отлёт врага не притягиваются к земле этим проходом.

### Стабильность походки

Контакт подошв при ходьбе и в стойке теперь решается двумя звеньями ноги (бедро/голень), с постоянной опорной высотой корпуса. Переключение опорной ноги больше не переносит весь скелет вверх/вниз; высота возврата после удара сглаживается. Амплитуда искусственного подпрыгивания процедурной походки уменьшена. Режимы падения и боевые позы сохраняют свои движения. Дополнительные проверки: `node tests/animation-transitions.mjs --gait` и `node tests/animation-transitions.mjs --gait --enemy` — по 481 кадру непрерывной ходьбы с контролем вертикальных скачков корпуса и контакта с землёй.

### Подготовка питья в Blender

Для следующего клипа создай отдельный Action `drink_bottle`, 30 fps, примерно 45–60 кадров: стойка → наклон и захват → подъём бутылки ко рту → глоток → возврат в исходную стойку. Не добавляй питьё в idle или walk. Сохрани текущий риг, его масштаб и общую ориентацию; анимируй контроллеры в Pose Mode, оставляя глобальное перемещение персонажа на месте. Первый и последний кадры должны совпадать с исходной стойкой. Включи Fake User у Action.

Добавь маркеры Action/Pose `grab`, `sip`, `end` — захват, глоток и возврат управления. Если удобнее, укажи эти номера кадров вместе с файлом. Пример: grab=12, sip=28, end=55. Для предпросмотра можно сделать отдельный объект `prop_bottle`, привязанный к кисти (`hand.r` для правой руки), не объединяя его с телом. Бутылку в игре и момент её привязки обработает код. После получения клипа нужно подключить его экспорт и начисление суперсилы на `sip`; в текущей сборке питьё ещё не подключено.

При коррекции опоры направление сгиба колена берётся из устойчивой продольной плоскости персонажа. Почти прямые ноги не используют шумный поперечный вектор исходного колена: это предотвращает сведение коленей внутрь при стойке и разворотах. Проверки `--idle` и `--idle --enemy` контролируют расстояние между коленями по всему циклу стойки; модульная проверка воспроизводит прежнее схождение на четырёх направлениях взгляда.

### Импульсы камеры

Короткая тряска разной силы включается на попаданиях кулаком, пинком, струёй, получении урона, рывке и супердобивании. Вращение и смещение накладываются после плавного слежения камеры и быстро затухают, без накопления дрейфа. Во время обычной ходьбы камера остаётся спокойной. Ограничения движения героя используют устойчивую камеру без импульса, поэтому тряска не перемещает самого персонажа. В паузе эффект заморожен; переключатель «Тряска камеры» сохраняется в браузере. По умолчанию учитывается системное уменьшение движения, пользовательский переключатель позволяет выбрать режим явно. Проверки: `npm test`, `node tests/camera-shake-smoke.mjs`, `node tests/encounters-smoke.mjs --first-area --shake`.

### Обновление авторских комбо
Из нового файла подключены `jab_01_combo` (15 кадров), `jab_02_combo` (10) и `kick_combo` (15), ходьба — 23 кадра при 30 fps. J / «Удар» переключает их по очереди; повторное нажатие после первых 15% текущего удара сохраняет один следующий удар. После паузы серия начинается заново. Отдельная кнопка пинка и K отключены. Длительность берётся из Action; необязательный Pose Marker `hit` задаёт момент попадания, без него — 90% клипа.

Скорость перемещения героя вычисляется из длины шага и длительности нового цикла. Для авторских поз ног повторный игровой IK отключён: сохраняются суставы из Blender, высота всей модели корректируется плавно с ограничением скорости. Допускается небольшой зазор подошвы до 2 см вместо резких сгибаний коленей.

### Визуальная настройка света
Открой игру с `?editor=lighting` (например, `https://syxelll.github.io/bomzh_game/?editor=lighting`). После загрузки откроется панель, игра встанет на паузу. В обычной ссылке редактор и кнопка в меню скрыты. Панель можно свернуть, чтобы рассмотреть всю сцену, либо закрыть и продолжить игру. Для повторного открытия: пауза → «Настроить освещение».

Доступны солнце (яркость, цвет, направление, высота), экспозиция, свет и цвета в тенях, туман и переключение теней. Есть три пресета. «Сохранить» хранит настройки на текущем устройстве и применяет их также в обычной игре. «Сбросить» возвращает исходный свет; нажми «Сохранить», чтобы сохранить сброс. «Скачать настройки» выгружает `dvor-lighting.json` для передачи; «Загрузить файл» позволяет восстановить вариант. Для установки выбранного света всем игрокам нужно перенести параметры JSON в `lightingDefaults` в `src/lighting.js` и опубликовать сборку. Это также единственное место для правки света через код; игровое направление солнца сохраняется при прокрутке бесконечной улицы.

### Ближняя камера и лёгкая глубина резкости
Основная камера приближена: расстояние 6,2 м при исследовании / 5,8 м в бою, на вертикальном экране 7,6 / 7 м. Наклон сверху уменьшен примерно до 7°, добавлено небольшое смещение по X для ракурса спереди сбоку. Камера следует за глубиной движения героя, чтобы он целиком оставался в кадре.

`src/depth-of-field.js` использует глубину основного рендера и один экранный проход. Фокус плавно следует за грудью героя, в добивании — за серединой пары. Резкая зона ±1,2 м; максимальный радиус размытия 2,5 CSS px на компьютере и 1,8 px на телефоне. Контуры ближних объектов защищены от размазывания, HUD рендерится браузером без размытия. Цвет обрабатывается в линейном HDR с одним применением ACES/цветового преобразования. На устройствах без HDR-буфера используется обычный цветовой буфер. Фокус и камера не двигаются в паузе. Для сравнения эффекта можно использовать `?dof=off`.

Проверки: `npm test`, `node tests/depth-of-field-smoke.mjs` (сравнение размытия в браузере на двух форматах экрана), обычный боевой smoke-тест.

### Предпросмотр высокой графики на телефоне

Добавь `?quality=high` к игровой ссылке: этот режим явно переопределяет автоматическое упрощение на узком экране. Разрешение рендера — до 2× CSS-размера с учётом DPR устройства, MSAA до 4× в основном буфере DOF, карта теней 2048 px. В обычной ссылке сохранён автоматический выбор; `?quality=low` принудительно включает облегчённый режим. Выбор по URL сохраняется при повороте экрана. Проверка: `node tests/high-graphics-smoke.mjs` эмулирует телефон 390×844 / DPR 3 и проверяет реальные размеры 780×1688 и MSAA.
