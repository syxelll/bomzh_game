# Дворовые истории — бесконечная улица

3D beat ’em up для браузера и Telegram Mini Apps. Иди вправо, побеждай группы противников и проходи как можно больше участков. Финального уровня нет; побочные задания, NPC и обмен бутылок сейчас убраны из режима.

## Запуск

Нужен Node.js 22.12+ (проверено на 24.19).

```sh
npm ci
npm run dev
```

Открой адрес после `Local:` в терминале. Команды выполняются в папке с `package.json`; окно сервера оставь открытым.

```sh
npm run build
node scripts/standalone.mjs
```

`dist/` — готовый статический сайт для HTTPS-хостинга. `dist/game-standalone.html` содержит код, модели и Actions в одном файле для открытия в настольном браузере без отдельного сервера. Telegram SDK исключён из одиночного файла. В обычной сборке подключены Telegram ready/expand; публичный хостинг и бот ещё не настроены.

## Управление

- WASD / стрелки или экранные кнопки — движение.
- J — кулак без расхода выносливости. Во второй половине удара можно заранее нажать следующий; третий удар серии усиленный и сбивает с ног.
- K — пинок (14 выносливости).
- L — вертушка по нескольким целям (32 выносливости).
- Пробел / «Рывок» — уклонение с короткой неуязвимостью (16 выносливости). Направление берётся из кнопок движения; без них — вперёд. Можно отменить свой удар.
- Esc / Ⅱ — пауза.

Выносливость восстанавливается после короткой паузы в использовании сильных приёмов. При получении урона герой кратко теряет инициативу; рывок позволяет уйти. Лежащие враги временно не атакуют и не получают повторных ударов, затем встают. Громила выдерживает кулаки без прерывания замаха.

## Бесконечное прохождение

Участки генерируются последовательно без последнего уровня. Растут характеристики врагов, размер группы и число волн. Одновременно приходит максимум четыре противника, позднее — до трёх волн за участок. Здоровье, скорость и урон имеют предел роста; дальше меняется последовательность стычек.

Перед боем камера плавно приближается. Видимых линий или ворот на земле нет. Враги создаются целиком за пределами текущего кадра и прибегают с его краёв; точка входа рассчитывается с учётом размеров экрана и текущего положения камеры. Пока группа не побеждена, герой остаётся в боевом кадре. После победы появляется «Дальше» и открывается следующий участок.

За победу над участком: 100 × номер участка очков, 8 здоровья и восстановление выносливости. Бутылки автоматически подбираются за 10 очков; каждая пятая восстанавливает 5 здоровья. Рекорд сравнивается сначала по пройденным участкам, затем по очкам и сохраняется в localStorage этого браузера. Общей сетевой таблицы лидеров пока нет. После поражения можно начать новый забег.

Окружение подгружается кусками: в памяти остаются пять соседних фрагментов улицы. Старое окружение и тела побеждённых противников удаляются; история участков не накапливается.

## Анимации из Blender

К герою подключены авторские Actions `idle`, `jab_01`, `kick` из присланного `.blend`. Их матрицы после вычисления ограничений Blender запечены в `public/models/hobo-actions.json` и применяются к существующему GLB. Текстуры повторно не запекались: геометрия и материалы игровые остались прежними, ранее запечёнными.

`jab_01` заканчивается вытянутой рукой; игровая версия плавно возвращает её в стойку после контакта. Контакт кулака синхронизирован с последним кадром Action, пинка — с кадром 10. Ходьба, вертушка и реакции пока процедурные. При переключении между авторскими и процедурными движениями используется короткий переход. Исходный `.blend` не изменён.

В текущей облачной среде оригиналы находятся в `/workspace/model-sources/`, исходные экспорты — в `/workspace/model-exports/`. Скрипты подготовки в `scripts/blender/` требуют Blender 5.2.3 и этих файлов. `export_user_actions.py` извлекает Actions без выполнения встроенных скриптов; пути настроены на облачную среду. Для запуска игры Blender не нужен.

## Проверки

```sh
npm test
npm run build
# Dev-сервер должен работать на порту 5173:
npm run test:browser
node tests/dynamics-smoke.mjs
npm run test:endless
node tests/animation-review.mjs
```

Браузерные проверки используют `/usr/bin/chromium` и программный WebGL; могут выполняться несколько минут. Проверяются управление, ресурс рывка, входы вне кадра, несколько участков подряд, ограниченный размер мира, авторские Actions и сохранение рекорда после перезагрузки. Модульные проверки генерируют 1500 участков и проверяют паузу, рекорды, разные размеры кадра и данные анимаций. Это не измерение производительности настоящего телефона.

Модели облегчены, текстуры запечены и встроены в GLB как lossless WebP. Инструменты повторной оптимизации находятся в `scripts/optimize-models.mjs` и зависят от сохранённых промежуточных файлов вне репозитория. Инструкции установки облачной среды используют `npm ci --cache /workspace/.npm-cache` из-за ограничений домашнего каталога.
